# 04 logDice 与原型性得分说明

> 本文说明数据中 logDice 指标的含义、原型性得分（PS）的公式与理论依据，以及 logDice 计算与义位筛选的先后顺序问题。
> 配套：每词 xlsx「PS计算」工作表已内置自动公式。

## 1. logDice 是什么

**logDice 是 Sketch Engine 的默认搭配强度指标**（Kilgarriff et al. 2014），在 Word Sketch JSON 与 xlsx 中即 `score` 字段，无需换算。

| 性质 | 说明 |
|---|---|
| 度量对象 | 词对在特定语法关系下的共现非随机性 |
| 取值范围 | 理论上限约 14（本数据实际范围约 2–13） |
| 标准化 | 不随语料库绝对大小变化 → **不同槽位、不同动词之间可直接比较** |
| 与 Fisher 精确检验 | 高度相关，均度量搭配的非随机性 |

选择 logDice 的两点考量（开题报告原文）：其一，标准化使跨槽位（PP 槽位 vs objects 槽位）、跨动词的原型性比较在方法论上成立；其二，与显著共现词项分析（Gries & Stefanowitsch 2004）的传统度量高度相关。

**重要**：logDice 由 Sketch Engine 在**词目层**、全义位聚合后一次性算出。研究者做不做义位筛选，都不改变其数值；筛选改变的是**哪些搭配词进入后续计算**（见第 3 节）。

## 2. 原型性得分（PS）

### 2.1 公式

```
PS = Mean_logDice × log₂(N + 1)
```

- **Mean_logDice**：所有「处理=保留」搭配词 logDice 的算术平均——**质量维度**（搭配典型性）；
- **N**：「处理=保留」搭配词总数——**广度维度**（搭配广度，对数压缩防止数量主导）。

### 2.2 理论依据

| 组成部分 | 来源/依据 |
|---|---|
| "原型成员拥有最多与范畴相关的特征" | Rosch (1978) 原型理论；特征数 ↔ 搭配词种类数 N |
| 特征重要性加权 | 搭配强度 logDice 作质量权重 |
| 乘积形式 = "特征数量 × 特征权重" | Rosch (1978) 原型度量的量化实现 |
| 显著共现词项分析法 | 王欢、林正军 (2022)；Gries & Stefanowitsch (2004) |
| 质量-广度双维度行为特征框架 | Divjak & Gries (2006) |
| logDice ≥ 3 显著阈值 | Sketch Engine 平台默认标准（Kilgarriff et al. 2014） |

公式为本研究在上述文献基础上设计的综合指标（质量 × 广度乘积整合），非直接引用。

### 2.3 操作流程（开题报告四步法）

1. **槽位确定**：从「词频概览」槽位汇总中，依据**数据断层**（logDice 断崖）与**功能验证**（独立构式不可互相替代）锁定编码范畴核心语义的槽位；成员句法行为不同时（arrive 不及物 vs reach 及物），以构式家族概念纳入同一比较框架；
2. **搭配词提取**：「搭配明细」表已按槽位列出前 50 搭配词（含 logDice、频次、典型组合、主题分布）；
3. **概念归类**：I 列填语义类别、J 列标「保留/剔除」——剔除标准为语义标准（见《03 意象图式提取说明》2.2），**必须独立于 logDice**，否则循环论证；
4. **PS 计算**：「PS计算」工作表内置 `COUNTIF`/`SUMIF` 公式，自动汇总 J 列="保留"的行数（N）与 logDice 总值，算出 Mean 与 PS。

### 2.4 基准数值（开题报告 arrive/reach 对比）

| 指标 | arrive | reach | 比值 |
|---|---|---|---|
| 核心槽位 | X at ... + X in ... | objects of X | — |
| 有效搭配词数 N | 60 | 25 | 2.4 : 1 |
| Mean logDice | 7.291 | 6.459 | 1.13 : 1 |
| **PS** | **43.23** | **30.36** | **1.42 : 1** |
| 综合判定 | 原型成员 | 典型成员 | — |

解读：PS 衡量各动词**在其自身核心构式变体上**的搭配典型性与广度，两种句法变体的 PS 在认知层面可比——比较的是谁在"到达"认知范畴中更具词汇代表性。PS 断层（1.42:1）即原型成员与典型成员的量化分界。

## 3. logDice 计算与义位筛选的先后顺序

**logDice 数值本身与义位筛选无关**：Word Sketch 不做词义消歧，搭配强度是词目层、全义位聚合后算出；筛选改变的是**哪些搭配词进入 PS**。

| 顺序 | 得到什么 | 风险/适用 |
|---|---|---|
| 筛选前算（词目全部搭配词） | 动词在范畴构式中的**整体**词汇代表性（词目层原型排序） | 多义污染：reach 的 objects 槽前 15 个中 12 个为抽象名词，不过滤会把"达成协议"的搭配强度混入"空间到达"的原型性 |
| 筛选后算（仅保留与 Y 类义位一致搭配词） | **义位层**原型性，与《修改稿》"分析单元是义位"一致 | 需人工语义归类；归类标准须独立于 logDice（语义标准，否则循环） |

**推荐顺序**（开题报告实际采用，本套数据的操作设计与此一致）：

```
义位准入判定（定性，Y/拓展/N）
   → 概念归类清洗（语义标准）
      → PS 计算（定量）
```

逻辑链："准入划定样本边界 → PS 在边界内排序"，避免"PS 排序把已判 N 的用法拉回"的循环。

**同时报告筛选前纯净度**（arrive 80% vs reach 20%）：它是独立于 PS 的语义集中度证据（开题报告表 19 的做法）。本套数据中「图式证据总览」的聚合搭配即为筛选前面貌，充当此层证据。

## 4. 论文表述建议（一句话）

> "搭配强度以 Sketch Engine 默认的 logDice 计量；清洗以义位语义标准进行；原型性得分（PS）在清洗后的搭配词集合上计算；清洗前的空间义纯净度另行报告，作为语义集中度的独立证据。"

| 位置 | 字段 | 说明 |
