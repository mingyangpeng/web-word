# docs/ 文档存放规范与地图

> 本目录的文件组织规范（2026-11 定稿）。**看到路径即知道：文档是什么、给谁看、
> 谁维护、是否还在演进。** 新文档入错目录＝漂移的开始。

## 一、存放规范（六类）

| 目录 | 定位 | 生命周期 | 维护者 |
|------|------|----------|--------|
| **spec/** | 平台设计与施工契约（架构规范、通用框架、协作规范、需求-实现对照） | **活文档**：随架构演进，修订须评审；与代码冲突以此为准 | 词典管理员（学术侧）／平台管理员（系统侧） |
| **help/** | 用户与编者帮助（功能使用说明、Word 版手册） | **活文档**：与功能同步交付——没有说明的功能不算完成；各页「📖 使用说明」面板的母本 | 全体（页面施工时同步迁入 page_guides） |
| **dev/** | 开发者文档：`ARCHITECTURE.md`／`CONFIG.md`／`TESTING.md`／`CHANGELOG.md`（自根目录迁入）、`design-system.md`、`reports/`（功能开发报告）、`reviews/`（评审轮次记录 R0–R5/S1–S3） | **追加型历史**：只增不改写 | 开发过程留痕 |
| **research/** | 研究资料（论文侧维护）：`tables/`（研究数据表 xlsx，**被灌库脚本引用，移动须同步改代码**）、`protocols/`（研究规程：判定标准/词表/开题）、`papers/`（journal 期刊论文工程／thesis 大论文／lexikos 论文源文档）、`notes/`（研究过程笔记） | 研究侧自主演进 | 研究者 |
| **archive/** | 已完结的过程文档（如监工协调），保留原措辞不再更新 | 冻结 | — |
| 根目录 | 仅保留 **README.md**（入口地图）与 **CLAUDE.md**（AI 助手配置，工具要求在根）——其余工程文档一律在 docs/ | 活文档 | 全体 |

`data/docs/` 是**数据域的原始研究底稿**（docx 源），归 data 目录纪律管，不入本规范。

## 二、命名与引用纪律

1. **代码可读路径仅限两处**：`docs/research/tables/`（灌库脚本读 xlsx）与
   `docs/help/平台功能使用说明.md`（帮助中心页读）。其余文档代码**不得**依赖；
2. 迁移文件必须同步更新全仓库引用（本轮已以文件名逐一定位替换并经全量测试验证）；
3. `archive/` 内文档保留写作时的原措辞（含当时路径），作为历史记录不回改；
4. Office 锁文件（`~$*.docx`）不入库、不入 git；
5. 新增文档先问三问：给谁看（定 spec/help/research/dev）？还在演进吗（否→archive）？
   会被代码读吗（是→仅限 research/tables 与 help）？

## 四、入口

- 平台功能怎么用 → `help/平台功能使用说明.md`（或 Web 界面「❓ 帮助中心」页）；
- 平台为什么这样设计 → `spec/平台架构设计规范.md`；
- 论文写什么 → `research/papers/`；
- 数据表在哪 → `research/tables/`（注意：灌库脚本按此路径读取，勿再移动）。

## 五、管理流程（v5.1 配套）

**责任分工**：spec/ 由词典管理员（学术条目）与平台管理员（系统条目）分轨维护，
交叉条目双签；help/ 由页面施工者随功能同一批交付；research/ 研究者自主；
dev/ 只追加不改写；archive/ 冻结。

**生命周期**：新建即入对应目录 → 活跃 →（被取代／已完结）→ archive/。
spec 版本记文件头履历；数据表用文件名版本（`_v0.2`、`_backup` 后缀沿用现有惯例）。

**四条铁律**：① 功能与说明一体交付（`test_page_guides` 锚点强制）；
② spec 与代码冲突以 spec 为准，故 spec 修订先于或伴随代码变更；
③ `docs/README.md` 地图是唯一索引，未登记＝不存在；
④ 代码可读路径仅限 `research/tables/` 与 `help/平台功能使用说明.md` 两处。

**spec 修订四步**：直接改文件（git 分支）→ 对应侧管理员评审 → 合并＋版本履历加行
→ 若影响功能界面，同步 help/ 对应章节。help/ 修订随功能走，无独立流程。

**例行维护（每阶段收尾）**：文档体检三查——地图登记核对、代码引用路径抽查
（`grep docs/` 验存在）、`~$` 锁文件与 .DS_Store 清理。不建外部文档平台
（零网络依赖），不搞文档编号体系（目录即分类）。
