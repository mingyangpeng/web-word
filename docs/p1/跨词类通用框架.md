# LexiSchema 跨词类通用建模框架（范畴包规范 v1.0）

> 目标：**一个引擎，多种词类**。换一个词类 = 换一个「范畴包」（Category Pack）目录，引擎代码零修改。
> 本规范定义范畴包的目录结构、每个文件的必填字段、引擎与配置的边界，以及接入新词类的验收标准。
> 配套：`configs/motion/`（移动动词，已按真实数据填好）与 `configs/speech/`（言说动词，虚构验证帧，
> 证明同一套结构能装下完全不同的词类）。

---

## 0. 核心抽象：什么是不变的，什么是要换的

```
┌─────────────────────────────────────────────────────────┐
│                      引擎（不变）                          │
│   义位管理 → 特征标注 → 信度计算 → Gower+UPGMA 聚类        │
│   → 图式聚合 → 模板实例化 → 检索/可视化/语料联动            │
└───────────────▲─────────────────────────▲───────────────┘
                │ 读                       │ 读
     ┌──────────┴──────────┐   ┌──────────┴──────────┐
     │   范畴包（每个词类一份） │   │   通用资源（跨词类共享） │
     │  configs/<category>/ │   │  语料接口(word sketch) │
     │  五个 YAML，见 §1     │   │  词典接口(OALD/现汉7)  │
     └─────────────────────┘   └─────────────────────┘
```

**不变的**（引擎层，任何词类通用）：
- 义位（sense）为分析单元的数据模型；
- 特征长表存储（sense × feature × value）；
- Gower 距离（按特征类型自动选择计算分支）+ UPGMA 层次聚类；
- 「图式 = 一组证据槽位 + 评分函数」的抽象；
- 「母图式 + 可变槽位 → 释义模板」的实例化机制；
- 信度计算（Krippendorff's α）、打标不删行、版本化。

**要换的**（范畴包，每个词类一份，共 5 个文件 + 1 个清单）：
- 特征集、图式体系、准入标准、AI 提示词、语料映射；
- 以及该范畴的义位清单本身。

**换词类的本质**：引擎问配置要答案，配置只回答三个问题——
**这个范畴里什么算一个义位（admission）？用什么维度刻画它（features）？
它按什么图式归类（schemas + corpus_map）？** 提示词（prompts）是这三问的自然语言表达。

## 2. 六个文件的规范与字段

### ① admission.yaml —— 准入标准（什么算一个义位）

```yaml
# 范畴：motion（移动动词）
version: 1.0
category: motion

# 操作性定义：判定一个义项是否属于本范畴的总标准
operational_definition: >
  义项描写实体运动体（自主主体）在物理三维空间发生整体位置移动，
  动词形式承载 [+运动] 与 [+路径/方式] 语义。

# 准入三分：每个候选义位必须被判为三类之一（引擎不解释语义，只存储标签）
admission_classes:
  - code: Y
    name: 核心物理位移义
    rule: 存在实体运动体 + 真实三维空间位移 + 可构建源点-路径-终点关系
  - code: EXT
    name: 隐喻拓展义
    rule: 无实体运动体，但空间位移图式投射至抽象域（保留为边缘成员）
  - code: N
    name: 剔除义
    rule: 静态方位义 / 纯状态变化义 / 与位移框架无关的抽象义

# 边界仲裁条款：两类交界处的裁决规则（引擎只要求"边界争议必须走这里"）
boundary_rules:
  - id: BR1
    between: [Y, N]
    rule: 原地振动/局部摆动类（整体无空间转移）判 N；瞬时坠落类（有运动体与路径）判 Y
  - id: BR2
    between: [Y, N]
    rule: 使役自移类（客体发生物理位移）判 Y，逐义位标注
  - id: BR3
    between: [EXT, N]
    rule: 仍以空间位移图式为基底者判 EXT（如"席卷"）；完全无位移框架判 N

# 候选池的来源与筛选链（记录用，引擎不执行）
candidate_pipeline:
  source: "Levin (1993) Ch.51"
  mechanical_screening: {positive_signals: 10, negative_signals: 17, kept: 358, of: 992}
  explicit_rules: {R0: 344, R1_removed: 6, R2_kept: 5, R3_review: 3, net: 352}
```

### ② features.yaml —— 特征集（用什么维度刻画义位）

```yaml
version: 1.0
category: motion

# 特征分组（组只用于展示着色，不参与计算）
groups:
  - {id: P, name: 路径, order: 1}
  - {id: M, name: 方式, order: 2}
  - {id: C, name: 动因, order: 3}
  - {id: A, name: 核验, order: 4}

# 特征逐条定义。value_type 决定 Gower 距离分支：
#   binary  → 不一致记 1；nominal → 不一致记 1；ordinal → 归一化后差值
features:
  - {code: P1, group: P, name: 源点凸显,   value_type: binary,  in_clustering: true,
     values: {0: 不凸显, 1: 凸显}}
  - {code: P2, group: P, name: 终点凸显,   value_type: binary,  in_clustering: true}
  - {code: P3, group: P, name: 有界达成,   value_type: binary,  in_clustering: true}
  - {code: P4, group: P, name: 轴向垂直,   value_type: binary,  in_clustering: true}
  - {code: P5, group: P, name: 速度,       value_type: ordinal, in_clustering: true,
     values: {0: 低, 1: 中, 2: 高}}
  - {code: M1a, group: M, name: 主体-人,     value_type: binary, in_clustering: true}
  - {code: M1b, group: M, name: 主体-动物,   value_type: binary, in_clustering: true}
  - {code: M1c, group: M, name: 主体-车辆工具, value_type: binary, in_clustering: true}
  - {code: M1d, group: M, name: 主体-无生液体, value_type: binary, in_clustering: true}
  - {code: M2,  group: M, name: 情态急促度, value_type: ordinal, in_clustering: true,
     values: {0: 轻缓, 1: 一般, 2: 急促}}
  - {code: M3a, group: M, name: 介质-陆地,  value_type: binary, in_clustering: true}
  - {code: M3b, group: M, name: 介质-水,    value_type: binary, in_clustering: true}
  - {code: M3c, group: M, name: 介质-空气,  value_type: binary, in_clustering: true}
  - {code: M3d, group: M, name: 介质-其他,  value_type: binary, in_clustering: true}
  - {code: C1,  group: C, name: 动因,       value_type: nominal, in_clustering: true,
     values: {0: 跟随依附, 1: 受迫, 2: 自主}}
  # ---- 核验区（不进聚类，聚类后核验句法行为一致性，防循环论证）----
  - {code: A1, group: A, name: 构式论元-不及物, value_type: binary, in_clustering: false}
  - {code: A2, group: A, name: 构式论元-及物使役, value_type: binary, in_clustering: false}
  - {code: A3, group: A, name: 主体受限标记,     value_type: binary, in_clustering: false}

clustering:
  algorithm: gower_upgma
  feature_scope: in_clustering   # 只取 in_clustering=true 的列
```

### ③ schemas.yaml —— 图式体系（义位按什么归类）

```yaml
version: 1.0
category: motion

# 图式是封闭清单：标注时四选一，不得新增（理论承诺）
# 每个图式 = 语义重心定义 + 证据面（在哪个语法槽位找证据）+ 评分函数
schemas:
  - code: MANNER_ACCOMP
    name: 方式伴随图式
    definition: 位移过程伴随的运动方式是语义重心
    classic_examples: [run, swim, limp]
    evidence_slots:            # 槽位代码见 corpus_map.yaml 的 slot 枚举
      - modifiers
      - adjectives_after
      - and_or_conj
      - subjects
      - usage_patterns
      - complements
  - code: SOURCE_DETACH
    name: 源点脱离图式
    definition: 运动体离开起始位置是语义重心
    classic_examples: [leave, depart]
    evidence_slots: [particles_after, objects_away, objects_off, objects_out, pp_from_outof]
  - code: GOAL_ARRIVE
    name: 终点抵达图式
    definition: 运动体到达目标位置是语义重心
    classic_examples: [arrive, reach]
    evidence_slots: [objects, objects_updown_in, pp_to_at_in, particles_with_obj]
  - code: INTERACT_MOVE
    name: 互动位移图式
    definition: 两实体同时位移且具空间互动关系
    classic_examples: [chase, accompany, follow]
    evidence_slots: [objects, pronominal_objects, pronominal_subjects, pp_after_behind]

annotation:
  mode: forced_choice          # 四选一
  secondary_schema: record     # 次要图式记入备注（供辐射网络）
  domain_merging:              # 图式→域的归并假设（可被义位层重聚类推翻）
    domains:
      - {name: 方式位移域, families: [MANNER_ACCOMP]}
      - {name: 路径位移域, families: [SOURCE_DETACH, GOAL_ARRIVE]}
      - {name: 互动位移域, families: [INTERACT_MOVE]}
```

### ④ corpus_map.yaml —— 语料证据映射（证据从哪来）

```yaml
version: 1.0
category: motion

corpus: enTenTen21
interface: sketch_engine_wordsketch   # 通用资源：word sketch 语法槽位

# 槽位枚举：本范畴用到的语法关系槽（语料接口是通用的，取用是范畴性的）
slots:
  - {code: subjects,           sketch_gramrel: "subjects of %w"}
  - {code: objects,            sketch_gramrel: "objects of %w"}
  - {code: modifiers,          sketch_gramrel: "modifiers of %w"}
  - {code: adjectives_after,   sketch_gramrel: "adjectives after %w"}
  - {code: and_or_conj,        sketch_gramrel: "%w and/or ..."}
  - {code: usage_patterns,     sketch_gramrel: "usage patterns"}
  - {code: complements,        sketch_gramrel: "complements of %w"}
  - {code: particles_after,    sketch_gramrel: "particles after %w"}
  - {code: objects_away,       sketch_gramrel: "objects of %w away"}
  - {code: objects_off,        sketch_gramrel: "objects of %w off"}
  - {code: objects_out,        sketch_gramrel: "objects of %w out"}
  - {code: objects_updown_in,  sketch_gramrel: "objects of %w up/down/in/into"}
  - {code: pp_to_at_in,        sketch_gramrel: "prepositional phrases (to/at/in)"}
  - {code: pp_from_outof,      sketch_gramrel: "prepositional phrases (from/out of)"}
  - {code: pp_after_behind,    sketch_gramrel: "prepositional phrases (after/behind)"}
  - {code: pronominal_objects, sketch_gramrel: "pronominal objects of %w"}
  - {code: pronominal_subjects,sketch_gramrel: "pronominal subjects of %w"}
  - {code: particles_with_obj, sketch_gramrel: "particles after %w with object"}

# 评分函数：图式重心指数（引擎提供两种内置函数，参数在配置里）
scoring:
  function: mean_logdice_log2n     # S = Mean_logDice × log2(N+1)
  top_k: 50                        # 每槽位取前 50 搭配词
  noise_filter:                    # 语义归类时的剔除提示（人工执行，配置仅提示）
    remove: [抽象概念名词, 隐喻投射名词, 量化时间状态名词]
    keep: [能指代或编码事件要素的词项]
```

## 3. 普适性验证：同一框架装下「言说动词」（虚构验证帧）

证明框架不是为移动动词量身定做——用完全不同性质的词类套同一结构：

```yaml
# configs/speech/features.yaml（节选）
category: speech
groups:
  - {id: I, name: 互动结构}
  - {id: S, name: 符号行为}
  - {id: R, name: 传信方式}
features:
  - {code: I1, group: I, name: 是否带受话论元,  value_type: binary, in_clustering: true}
  - {code: I2, group: I, name: 是否带引语论元,  value_type: binary, in_clustering: true}
  - {code: S1, group: S, name: 声道使用,        value_type: nominal, in_clustering: true,
     values: {oral: 口头, written: 书面, sign: 手势}}
  - {code: R1, group: S, name: 信息取向,        value_type: ordinal, in_clustering: true,
     values: {0: 描述, 1: 指令, 2: 表情}}          # ← 序数与移动动词的 P5 同机制
  - {code: R2, group: S, name: 正式度,          value_type: ordinal, in_clustering: true}
  - {code: A1, group: A, name: 构式论元-直接引语, value_type: binary, in_clustering: false}

# schemas.yaml（节选）
schemas:
  - {code: ASSERT,   name: 断言图式,   definition: 传递命题信息为重心,  classic_examples: [say, state]}
  - {code: DIRECTIVE, name: 指令图式,  definition: 促使受话行动为重心,  classic_examples: [order, request]}
  - {code: EXPRESSIVE, name: 表达图式, definition: 情感态度外化为重心,  classic_examples: [complain, praise]}
```

**对照结论**：移动动词的「速度（ordinal）/主体四分（nominal）/介质（binary）」与言说动词的
「正式度（ordinal）/声道（nominal）/引语论元（binary）」落在**完全相同的字段结构**里；
四图式换三图式、六槽位换八槽位，引擎读到的都是同一套键名。框架成立。

## 4. 引擎与配置的边界（哪些改动允许、哪些禁止）

| 引擎层（禁止为词类定制） | 范畴包层（每个词类自己定） |
|---|---|
| Gower 距离按 value_type 自动分支 | 特征叫什么、分几组、值域是什么 |
| UPGMA 聚类与 cophenetic 评估 | 图式有几个、各管什么证据槽位 |
| α 信度计算与分歧定位 | 准入三分的语义与边界条款 |
| 母图式+槽位→模板的实例化机制 | 提示词口诀与占位符取值 |
| 打标不删行/版本化/导出 | 域归并假设（可被重聚类推翻） |

**纪律**：引擎代码里出现任何具体词类的名词（如「方式伴随」「P5 速度」）即为违规——
现有代码中的三处硬编码（FEATURE_COLUMNS、四图式名、提示词口诀）迁移方向就是本文 §2 的六个文件。

## 5. 新词类接入流程（四步）与验收标准

```
第一步 复制模板    cp -r configs/_template configs/<new_category>
第二步 研制配置    填六件套：准入标准（最重）、特征集（含类型）、图式、语料映射、提示词、元信息
第三步 灌注义位    义位清单按 admission.yaml 三分筛选后入 cs_lexemes/cs_senses（category 字段隔离）
第四步 自检启动    引擎加载时跑 pack.yaml 的 selfcheck，全过才开放该范畴页面
```

**「复用验证」的客观判据**（思路文档第 16 步的验收标准，一句话版）：
> 在第二个范畴上，仅通过编写配置包（不改引擎代码）走完
> 「义位筛选 → 特征标注 → 聚类 → 图式提取 → 模板实例化」五步，即验证复用成功。
