# LexiSchema 论文 vs 平台现状：白话版对照

> 先用一段话讲清楚三个东西的关系，再看清单。
>
> **《给师兄讨论-Project的思路》** = 研究的「总计划书」：想做一个什么研究、分几步走。
> **《Lexikos Project的写作-261104》** = 按总计划书写的**论文草稿**，同时它列出了支撑这篇论文需要的**平台功能**（平台叫 LexiSchema）。
> **本仓库（MOVECAT/web-word）** = 已经建好的**真实平台**。
>
> 问题：论文草稿里描写的 LexiSchema，和真实平台**不是一模一样**。有的功能草稿写了、平台真有；有的草稿写了、平台没有；有的平台有、草稿忘了写。下面就是把这三堆东西分清楚。

---

## 一、先看懂：论文要平台做什么（用人话）

论文草稿说的 LexiSchema 平台，要干 6 件事：

1. **管数据**：把 171 个移动动词、996 个义项管起来，编好号（论文 §1–3）
2. **打标签**：给每个义项标语义特征（18 个特征：跑多快、谁在跑、什么姿势…），而且要**两个人独立标**，算一致性分数（Krippendorff's α，≥0.7 才算过关）（论文 §4）
3. **自动分类**：用聚类算法把意思相近的义项自动归堆，每堆里再分「最典型 / 一般 / 边缘」三级（论文 §5）
4. **提炼图式**：每一堆共有的「事件框架」提炼成模板（论文 §6）
5. **生成释义**：按模板自动生成释义初稿，编者改定稿（论文 §6）
6. **配套检索**：能搜词、能用一句话搜意思、能看关系图、能查语料例句（论文 §7）

## 二、已实现 ✅（平台真有，论文可以放心写）

**一句话：论文的第 1、3、4、6 件事基本都有，第 2 件事有一半，第 5 件事只有雏形。**

| 论文要的 | 平台真有的 | 举例说明 |
|---|---|---|
| 管数据（§1–3） | 171 词、996 义位全部入库，25 张 MySQL 表，一键灌库 | 运行 `./start` 一条命令，全部数据自动进库，还有体检脚本验收支 |
| 词池怎么来的（§3.1） | Levin 216 个候选 → 层层筛选剩 171 个，每个淘汰的词都写了原因 | 比如「原地打转」的词（spin 类）位移语义弱，被淘汰且留痕 |
| 18 个特征（§3.1 表1） | 和论文完全一致：15 个进聚类 + 3 个只做事后核验 | P1–P5 管路径（有没有终点、快不快），M 组管方式（谁在跑、步态），C1 管动因（自愿跑还是被迫逃） |
| 自动分类（§5） | 跑范畴试点已真跑完：英语 5 簇、汉语 5 簇，质量分 0.825/0.795 | 例如英语簇1「短距冲刺类」：run 跑完里程、sprint、charge、dash 四个义项聚在一堆 |
| 图式体系（§6.1） | 四种运动图式 + 每种图式看哪些语法槽位 + 重心打分 | run 的「方式伴随」得分 54.19 遥遥领先，所以判为方式图式 |
| 配套检索（§7.1 第一模式） | 搜单词→出全部义项、特征、簇归属 | 平台搜「walk」直接出 24 个义项 |
| 查语料例句（§7.3） | 171 个词的搭配明细 69,943 行，逐词可下钻 | 查「sweep」能看到 foot(12.1)、mop(11.31) 等搭配证据 |
| 词与词关系图（§7.2） | 171 词力导向图，能拖能点，点节点出词条卡片 | 全屏可视化，点「run」看到它的 39 个义项和近义词 |
| 界面 | 六个页面全部可用：搜索/图谱/语料/域系/标注/范畴深挖 | 不缺 UI，论文配图可以直接截图 |

## 三、未实现 ❌（论文写了、平台没有——投稿前必须处理）

**按危险程度排序，分三档：**

### 🔴 第一档：可能影响论文能不能发表（2 件）

| 缺什么 | 大白话解释 | 两条路 |
|---|---|---|
| **两个人独立打标签 + 算一致性分数 α** | 论文 §4 整章讲信度检验。平台现在只有**一个人**（+AI 草稿）打的标签，没有第二个人独立标过，所以 α 算不出来。审稿人问「你的分类结果可信吗」，这是最要命的软肋 | ① 找同学/同事按手册独立标 15%–20% 的样本，然后算 α（最稳）② 论文里如实写「双人标注进行中，α 下一步报告」（可行但削弱 §4） |
| **平台能不能上网访问** | 师兄发表的 BILEX 论文里平台有官网（bilex.top）。Lexikos 审稿人会期待能点开看看。现在平台只在你电脑上 | ① 部署到公网（Streamlit 有现成方案）② 论文写「内网原型+截图」，但要接受审稿人看不到实物的风险 |

### 🟡 第二档：论文两大核心产出，缺程序引擎（3 件）

| 缺什么 | 大白话解释 | 工作量 |
|---|---|---|
| **自动生成释义模板的引擎** | 论文 §6 是重头戏：聚类完每一堆要自动生成「带槽位的释义模板」。现在只有 3 个**手工做**的例子（run/jog/march），没有能批量生成的程序 | 中等偏大。难点：模板槽位要同时接「图式槽位」和「特征编码」两套数据 |
| **谱系树图（dendrogram）** | 论文 §5.1 说聚类产出「谱系树」可交互切割。图没有画出来 | 小。scipy 现成函数，约 1 小时 |
| **典型性自动排序** | 论文 §5.2 说每簇按「到簇代表点的距离」分原型/次典型/边缘三级。现在是靠人看特征画像判读，没有程序算 | 小。代码量很小（就是算每行到簇中心的距离再排序） |

### 🟢 第三档：锦上添花型缺口（4 件，论文可以「如实带过」）

| 缺什么 | 大白话解释 | 处理 |
|---|---|---|
| **一句话搜意思**（AI 语义检索） | 论文 §7.1 的第二模式：输入「一个士兵整齐地走」→自动找到 march。现在只能搜单词 | 论文写「设计预留」即可，不算硬伤 |
| **拖动滑块实时重新分类** | 论文 §5.1 说可以交互调整切割线。现在是固定的 k=5 结果 | 同上 |
| **义位级的语义图** | 现有图谱节点是「词」，论文想要节点是「单个义项」、连线粗细=语义距离 | 论文可以改口为「词级图谱+义位级热图」两件套 |
| **模板批量导出** | 生成的模板一键导出表格/文本 | 依赖模板引擎，有了引擎顺手就有 |

## 四、平台有、但论文忘了写 📝（白捡的亮点，建议补进去）

| 平台真有的 | 论文为什么该写 | 举例 |
|---|---|---|
| **AI 打草稿 + 人做决定 的完整流水线** | 这是「人机协同」卖点最有说服力的证据，论文只在 §3.2 提了一句 | AI 先给 352 个义项打标草稿，全程存档；limp 这个词 AI 主动标注「汉语书面语是'跛行'、口语是'一瘸一拐'，选哪个会翻转对齐等级」——这种细节审稿人爱看 |
| **三层质量关卡** | 论文讲质控只有一句，实际有三道关 | ① 机器规则初筛（992→358）② AI 初筛（162 个文件、只当候选）③ 人工全量复核 |
| **三个「差点被骗」的案例** | 证明「光看统计数据会出错」，非常出彩 | tear 的数据被「撕裂」义污染、sweep 被「打扫」义带偏、ferry 看似互动其实是运送——三个案例说明为什么必须人工复核 |
| **英汉双语已经打通** | 论文 §3.4 说「未来可迁移到其他语言」，其实**汉语已经做完了**：《现汉7》7 万词条全入库，跑范畴英汉聚类对齐也做完了 | 这是「迁移能力」的现成证据，不用等未来 |
| **查出来是错的会如实说** | 体现学术诚实，跟范文 BILEX「不编造」一脉相承 | 词目释义只有 2.9% 是词典原文，页面直接标出来；音标缺了就写「未收录」绝不猜 |
| **工程成熟度** | Project 栏目喜欢「能跑的真系统」 | 25 张表有验收基线，一条命令体检 23 项；断网/没 key/没库都能降级运行不崩 |

## 五、《给师兄讨论-Project的思路》单独提出、平台还没做的

（跟上面重复的已去掉，这是思路文档**特有**的要求）

| 思路文档要的 | 大白话 | 状态 |
|---|---|---|
| 标注信度不达标时的**整改闭环**（改规范→重标→再算 α） | 流程设计里有「不合格就打回重来」的循环，因为第一轮双人标注还没开始，这个循环也就没跑过 | 🔴 跟第一档同源 |
| **图式和图式之间的「族谱」** | 现在只有四种图式各自的定义，没有画「这四种图式谁跟谁更亲近」的谱系 | 🟢 论文可写为展望 |
| **换一个词类也能用**（配置化复用） | 思路文档的最终卖点：换一套特征配置就能分析别的词类（比如情绪动词）。平台架构上留了口子，但**没真的用第二个词类跑过一遍**。注意：现汉7 是「换语言」，不算「换词类」 | 🟡 论文措辞要小心：写「架构预留」而非「已验证复用」 |
| 两份标注自动找不同 | 双人标注后系统自动挑出两人不一致的条目 | 🔴 依赖第一档的双人标注 |
