## 0. 定位与最终产出

**以义位为中心、配置驱动、人机协同的词典语义建模与编纂平台。**

1. 最终产出**不是页面，是一部结构化、版本化、可导出的词典数据库**：页面是加工车间，
   出版＝数据库快照，修订＝快照间的版本演进；
2. 双形态服务：编纂端（编者，内网重交互）＋查阅端（读者，公网只读镜像）；
3. 论文身份：Lexikos 论文的工具层贡献（词典学／方法学／工具三贡献之一），
   界面镜像论文章节（§4–7），审稿人逐章可核对；
4. 扩展方式：**一个引擎、多种词类、可插拔工具**——换词类只换配置，新工具按插件接入。

## 1. 五构件（D · C · P · A · U）＋工具层 T

| 构件 | 定义 | 关键纪律 |
|------|------|----------|
| **D** 义位权威库 | 唯一事实源，九数据域，一切落库留痕 | 版本化、不删行、有备份；义位唯一锚 `oald_senses.id` |
| **C** 配置定义层 | 三层治理（§7） | 改研究方案的进文件，改运营状态的进界面 |
| **P** 编纂工序链 | 四阶段十五道工序＋六闸门（§3） | 未过闸不出工序；未启用工具不渲染 |
| **T** 工具注册表 | ToolSpec 插件契约（§4） | 新工具接入零架构改动、零 DDL 迁移 |
| **A** 协作智能层 | 三通道缠绕每道工序（§5） | AI 只出候选与证据，永不直写 D |
| **U** 编者界面 | 七区菜单＋义项脊柱＋协作收件箱（§9） | 菜单镜像论文；页面＝管线与注册表的渲染器 |

关系式：**C 定参数与开关 → P 在 D 上做变换 → T 提供每道工序的能力 → A 在每道工序插入
「AI 提案→人裁决」→ 裁决写回 D 成新版本。**

（2026-11-12 对齐实现口径，批次 30 起：五构件支持词典管理员级勾选启停——
module_plugins 表持久化，停用为入口级开关不撤数据，重新勾选即恢复；锁定项 C/U
——配置定义层是引擎输入、编者界面层是查阅底线，勾选框置灰不可停用；停用模块
侧边栏入口隐藏＋页面直访拦截 fail-closed。）

## 3. 编纂工序链（四阶段十五道＋六闸门）

```
Ⅰ 筹备      1 词典设计(体例) · 2 语料建设(许可闸门) · 3 收词定表
Ⅱ 语义分析  4 义位准入 · 5 特征标注 · 6 信度检验 · 7 聚类归类
            · 8 义项分立复核 · 9 图式模板
Ⅲ 编纂成文  10 释义撰写 · 11 例证配置(含多模态) · 12 标签与对译(三态)
            · 13 审校定稿 · 14 词条装配
Ⅳ 发布      15 出版导出(许可强制＋体例终检＋内容域快照)
    ↑___________ 反馈回流（查询/评分 → 工序5 重标 / 工序10 改释义）___________|
```

**闸门表（放行条件）**

| 闸门 | 条件 | 拦下什么 |
|------|------|----------|
| G1 准入→编码 | 义位判 Y/EXT（N 类不进建模） | 脏义位 |
| G2 信度→分析 | 该特征 α≥0.7；不达标走「规范修订→重标」闭环 | 不可信矩阵 |
| G3 分立→释义 | 该簇分立复核定稿（义项清单锁定） | 未定清单上写释义 |
| G4 撰写→审校 | 编辑提交＋AI 体例质检通过 | 不合规文本 |
| G5 审校→装配 | 终审 approved（两级制，见 §8） | 未审文本 |
| G6 装配→出版 | 许可检查（释义改写率＋媒体授权）＋体例终检＋备份新鲜 | 侵权/脏快照 |

**工具裁剪**：十五道＝能力全集；各词典项目按启用工具实际运行
（preset：`full` / `monolingual` / `lexicon_only`）。`disabled`（配置关，不渲染）
≠ `enabled+empty`（已启用未灌数据，降级提示）。

## 4. 工具插件体系（T 层）

每个工具实现统一契约，注册进中央注册表（`src/tools/registry.py`）：

```python
class ToolSpec:
    id = "alignment"              # 稳定 id（settings/运行记录引用）
    name = "图式对齐"; version = "1.2.0"
    stage = "alignment"           # 绑定的工序
    deps = ["corpus_map.yaml", "zh_dict"]   # selfcheck 依赖声明
    params_schema = {...}         # 可界面调的运行参数（方法参数仍在 pack.yaml）
    ai_hooks = ["draft", "audit"] # 接哪些 A 通道
    ui_surface = "tab:semantic_analysis"    # 渲染位置
    permission = "editor"         # 最低使用角色
    def check_deps(self): ...     # selfcheck 调用
    def render(self, ctx): ...    # U 层渲染
    def run(self, ctx): ...       # P 层执行
```

- 内置十类：准入、特征标注、信度、聚类、典型性、图式、对齐、模板、语义检索、语料证据（＋multimedia）；
- **两步激活**：平台管理员维护 **available**（安装/依赖/selfcheck 就绪）→
  词典管理员 **enabled**（工作方法决策，界面点亮＋调运行参数）；
- **新工具接入五步**：实现 ToolSpec → 注册（一行装饰器）→ pack.yaml 声明引用 →
  selfcheck 绿 → 界面点亮。引擎零修改、无 DDL 迁移；
- selfcheck 双校验：工具依赖自洽＋pack 引用 ⊆ 注册表；
- **可复现**：每次聚类/信度/导出运行记录 工具启用快照＋tool_id＋tool_version。

## 5. A 协作智能层

**三通道**（每道工序至多三挂钩，按需启用；裁决支持单条/批量）：

| 通道 | 方向 | 典型行为 |
|------|------|----------|
| 草稿 | AI→人 | 准入/特征/图式草稿；主动学习排序；义项合拆提议；模板批量生成；配图/视频推荐；枚举属性预填；导入异常检测；分派建议（仅按在途负荷） |
| 探针 | 人↔AI | 库内受控问答附证据链，无据明说「无据」；轻量留痕（kind=probe，不进收件箱） |
| 质检 | AI→人 | 第三标注员预演预警；簇画像冲突报警；替换性测试；体例/句式/定义词表检查；文图一致性；许可终检 |

- **资源注入协议**：提示词＝①配置规则（C）＋②库内证据（D）＋③任务指令（prompts/）；
  输出分层标注来源——「依据配置规则 X／库内证据 Y／模型推断 Z」；
  **AI 不背词库，AI 查词库；查不到就说查不到**；
- **不确定度口径**：规则层未命中特征数＋历史人-机分歧率＋预演分歧标记
  （禁用 LLM 自报置信度）；
- **留痕**：`ai_proposals`（kind: draft/audit/probe）带提示词版本＋资源快照版本＋采纳/否决记录；
- **度量**（协同度量页＋论文表格）：采纳率、AI-人一致率 vs 人-人 α、标注节省量、
  替换测试通过率、打回率、体例质检通过率。

## 6. D 义位权威库（九域＋三脊柱＋词条模型）

```
① 词条资源域   oald_senses 996 · 现汉7 三表 · definitions(词目层=展示投影,待退役)
               · wordforms(词形表：inflection/variant/pinyin，检索词形还原用)
② 语料证据域   enTenTen21 搭配 69,943 · 词频/图式得分 · 域系 352
③ 范畴研究域   categories · cs_lexemes/senses(＋status/merged_into) · cs_sense_features
               · cs_cluster_runs(版本化) · cs_clusters · 英汉对齐
④ 编纂成文域   definition_versions(＋style_version) · sense_examples · sense_translations(三态)
               · review_tasks · review_comments
⑤ 协作留痕域   users(＋must_change_password) · user_roles(多角色) · project_members
               · assignments(＋round[含 training]/scope_clusters) · annotation_submissions
               · adjudications · reliability_runs · ai_proposals(draft/audit/probe)
⑥ 资源发布域   feedbacks · usage_logs(＋user_id 可空) · resource_registry(许可必填,双人双签)
               · export_batches · category_tool_settings(tool_id VARCHAR＋version)＋settings_audit
⑦ 媒体资产域   media_assets(kind/source/license/sha256) · media_bindings(四锚：词目/义位/例证/图式)
⑧ 词典项目域   dictionary_projects(＋chief_id) · import_batches(＋批次回滚)
               · custom_fields / custom_values(定制属性)
⑨ 用户上下文域 user_profiles · user_state(工作位置/续接点) · user_bookmarks · user_notes
               · draft_states(未提交表单自动保存)
```

- **义位唯一锚＝oald_senses.id**，语义类数据一律挂它；媒体为展示层资产，允许词目锚
  （word＝definitions.id 投影层）；
- **三版本脊柱**：annotation_submissions→cs_cluster_runs→definition_versions
  （＋ai_proposals、export_batches）——任何一版释义可答「谁标的、α 多少、哪版模板、
  AI 提了什么、谁定稿」；
- **装配确定性**：词条装配＝纯函数(义位版本, 体例版本, 装配器版本)，不单独版本化；
- **备份三件套**：每日 mysqldump＋每周卷快照＋每月离线副本（含媒体）；恢复演练永不指向
  生产库；审计日志永久保留（含敏感查看留痕）。

**成品词条内容模型**：

```
词条 run
├─ 头块：词形 · 音标 · 🔊发音(TTS自产/授权) · 词性 · 屈折 · 句型
├─ 义项区：原型梯度排序；建模义位(模板释义)＋非建模义位(沿用OALD/现汉,标来源)；coverage 标注
├─ 多模态区：释义配图 · 动作视频示范 · 图式示意图（style.yaml 位规则）
├─ 例证区：文字例证＋媒体例证(caption＋来源)
├─ 辨析栏：同簇英汉对照 · 参见：同簇互见/反义/图式同源
├─ 词源栏（可选微结构，style.yaml 决定）
└─ 定制属性区：项目自定义字段（语域/教材分级/频级…）
```

## 7. C 配置治理（三层）

| 层 | 载体 | 内容 | 谁改 |
|----|------|------|------|
| 词典层 | 文件（git） | style.yaml：定义词表、替换性检验、义项排列（原型梯度为主/频次校验）、括注/辨析/参见、多模态位规则、可选微结构 | 研究者（评审制） |
| 范畴层 | 文件（git） | 六件套＋pack.yaml 工具引用与方法参数（sampling/算法） | 研究者（评审制） |
| 运行层 | 界面＋DB | category_tool_settings（enabled＋运行参数）＋预设＋审计 | 见 §8 分工 |

原则：**改研究方案的进文件，改运营状态的进界面**。selfcheck 双校验（依赖自洽＋
pack ⊆ 注册表）；每次运行记工具状态快照。

## 8. 协作体系（六角色 · 两范式 · 一底座）

**六角色**（user_roles 多角色，一人可叠加；新号默认 viewer）：

| 角色 | 职责 | 继承 |
|------|------|------|
| **词典管理员** | 项目成员增删与项目内授权、任务分配/改派/轮次、工具点亮、体例裁决（变更工单）、终审终裁（例外通道）、出版批准（含出版导出 tab 的资源登记数据面）、项目广播、主编驾驶舱 | reviewer |
| **平台管理员** | 项目壳创建并指定首位词典管理员、账号生命周期（建号默认 viewer/启停/密码重置）、工具 available、数据库管理（备份/恢复/清理）、系统体检 | viewer |

（2026-11-08 对齐实现口径：资源登记的数据面在词典管理员·词典管理区「📤 出版导出」
tab 内，不归平台管理员·系统管理区——与功能使用说明 §7.5 一致，实现跟随母本。）
| reviewer / editor / annotator / viewer | 审校仲裁 / 簇承包撰写 / 盲标 / 只读 | — |

**三级最小权限链**：平台管理员建号（viewer）→ 词典管理员入册（project_members 项目内职能）
→ 词典管理员分派（assignments 具体簇）。任何一级缺失，下游不生效；平台管理员不得自行提权。

**两协作范式**：

| | 标注协作（判断类：工序 4–8） | 编纂协作（表达类：工序 10–13） |
|---|---|---|
| 模式 | 盲标独立→分歧仲裁→α | 簇承包→多轮审校（回避制）→定稿 |
| 分派 | 抽样 15–20%（round 含 training 试标轮：金标比对达标才开正式轮） | 按词簇承包（义位集合限同簇） |
| 度量 | 人-人 α | 审校轮次、打回率、体例一致性 |

**关键规则**：
- **两级终审**：普通词条 reviewer 终审即 final；争议词条（仲裁后存疑/申诉/抽查）升级
  词典管理员终裁——终裁是例外通道，不是必经站；
- **回避制无豁免，含词典管理员**（自写词条 reviewer 终审；单主项目走 bypass 公示）；
- **改派**仅限 draft/rejected 状态；停用用户强制先改派在途任务；
- **任务×角色矩阵**：撰写/例证/对译→editor+；审校→reviewer+；标注→annotator+；
  分立双评→annotator+reviewer；装配/出版→词典管理员；负荷上限入运行层配置（默认 10）；
- **主编驾驶舱**：全书进度漏斗＋风险清单（超期/α 未达标/审校积压/打回率异常）＋待我裁决汇总；
- **协作收件箱四类**：AI 建议待裁决／待我审校／分派给我的任务／**待我裁决**（词典管理员置顶）；
- **项目广播**：project_announcements（登录横幅＋收件箱类目）
  **（2026-11-10 对齐实现口径：表名为 `project_broadcasts`；形态为协作收件箱置顶
  横幅——展示登录用户在册项目最新一条广播，发布入口在词典管理·项目成员 tab
  「📢 项目广播」段，标题 ≤200／正文 ≤10000）；**
- **一致性四防线**：簇承包、style.yaml 硬准绳、AI 体例质检、终审抽查＋出版终检。

## 15. 数据出入口纪律（v5.1 增补）

> 词典是核心资产：数据的「出去」与「进来」**同权管控**；看数据按角色分级，带数据只有词典管理员。

**内容性导出**（模板/特征矩阵/分歧清单/词条数据/定制属性/反馈统计/出版快照/查阅镜像）：
唯一权利人＝**词典管理员**；界面按角色隐藏＋服务端中央闸门 `require_dict_admin()` 拦截
（不是只藏按钮）；每次导出写审计（操作人/数据集/行数/时间）。实现口径：中央闸门函数
＋ToolSpec 动作级权限位（export 归 dict_admin）。

**运维性备份**（灾备快照/恢复演练）：平台管理员，目的限于灾备；备份文件按敏感数据
受控存放、**不得用于对外交付**——对外交付必须走词典管理员的出版导出（G6 闸门）。

**导入同权**：数据入口与出口同管——导入向导/批量灌库的业务数据操作仅词典管理员；
平台管理员不碰业务数据（只管系统与账号）。

**豁免**：个人上下文（本人的笔记/收藏/查询历史）本人可导——属用户私有数据，
不是词典资产；聚合统计的导出仍归词典管理员。

**口径修订**：《多人标注系统设计规范.md》§1 viewer「只读（统计、导出）」自 v5.1 起
修订为「只读统计」；导出权归词典管理员。

**单点缓解**：重要词典项目建议配置 ≥2 名词典管理员（多角色模型已支持）；
单人项目关键动作走 bypass 留痕＋项目广播公示兜底。
