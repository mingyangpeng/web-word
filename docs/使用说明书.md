## 一、这是什么

**LexiSchema** 是一个以义位为中心、配置驱动、人机协同的词典语义建模与编纂平台。它把词典编纂的全流程——从语料证据采集到释义定稿出版——搬到了线上，让编者的时间花在**判断**上，而不是**抄写和检索**上。

一句话：**你给词，它帮你分析、聚类、生成释义；你审校，它帮你留痕、出版。**

## 二、快速启动

### 2.1 Docker Compose（推荐）

```bash
# 解压部署包后
cd lexischema-deploy-*

# 编辑 .env 设置密码（必改！）
vi .env
# MYSQL_PASSWORD=你的安全密码
# MYSQL_ROOT_PASSWORD=你的安全root密码

# 启动
docker compose up -d

# 打开浏览器
open http://localhost:8501
```

### 2.2 本地 Python（无 Docker）

```bash
# 前置：Python 3.11+、MySQL 8.0
pip install -r requirements.txt

# 建库
mysql -u root -e "CREATE DATABASE web_word_db CHARACTER SET utf8mb4;
CREATE USER 'web_word_user'@'localhost' IDENTIFIED BY 'webword123';
GRANT ALL ON web_word_db.* TO 'web_word_user'@'localhost';"

# 配置
cp .env.example .env

# 灌库＋启动
chmod +x start start.sh develop.sh repair.sh
./start
```

## 三、账号与角色

平台有**六个角色**，新号默认 viewer（只读），由词典管理员逐级授权：

```
平台管理员建号（viewer）
    → 词典管理员入册项目（project_members 项目内职能）
        → 词典管理员分派任务（assignments 具体簇）
```

| 角色 | 谁授的 | 能做什么 |
|------|--------|----------|
| **词典管理员** | 平台管理员 | 管编者、分派任务、配供应商、体例裁决、终裁、出版 |
| **平台管理员** | 系统初始化 | 建号（默认 viewer）、供应商 available、备份、体检 |
| **审校** | 词典管理员 | 初审/终审释义、仲裁分歧 |
| **编纂员** | 词典管理员 | 簇承包撰写释义、配例证、定对译 |
| **标注员** | 词典管理员 | 盲标特征编码、准入判定、分立双评 |
| **只读** | 平台管理员 | 浏览统计 |

**三级最小权限链**——任何一级缺失，下游不生效。

## 五、核心工作流

### 5.1 编纂员：从领任务到出释义

```
① 词典管理员在「📋 任务分配」把某簇分派给你
② 你在「📥 协作收件箱」看到新任务
③ 打开「✍️ 撰写台」：模板预览打底→成文编辑→保存→提交审校
④ 审校人在审校台：初审→意见线→打回或通过
⑤ 你按意见修订→重提→终审通过→定稿
⑥ 词典管理员在「📤 出版导出」生成快照
```

### 5.2 标注员：从领任务到出 α

```
① 词典管理员分派标注任务（抽样 15-20%）
② 你在「📥 收件箱」看到任务（AI 草稿已预填）
③ 打开「🏷️ 标注任务」：认/改/问（点「为什么」看证据链）
④ 提交→进入 f₃ 信度计算
⑤ α≥0.7 达标→特征矩阵锁定→流入聚类
```

### 5.3 词典管理员：从建项目到出词典

```
① 🔧 账号管理：建号（默认 viewer）
② 📖 项目成员：入册＋授项目内角色
③ 📥 数据导入：词条文档加载＋映射＋批次台账
④ 📚 词条浏览器：确认数据完整
⑤ 🏷️ 定制属性：定义项目字段
⑥ 📋 任务分配：分派＋看板
⑦ 📐 体例配置：定义项排列/定义词表/替换检验
⑧ 📤 出版导出：G6 闸门→快照→发布
```

### 6.2 覆盖阶梯

```
996 全义项（OALD 拆分）
 └─ 352 建模义位（准入 Y+EXT）
     └─ 32 跑范畴试点（特征编码＋聚类＋模板）
         └─ definition_versions（释义成文，随编纂进度增长）
```

coverage 标注在词条装配预览与词条浏览器中如实展示。

### 6.3 版本脊柱

任何一版释义都能回答「谁标的、信度多少、哪版模板、AI 提了什么、谁定的稿」：

```
annotation_submissions（标注层）
  → cs_cluster_runs（分析层，版本化）
    → definition_versions（释义层）
      → export_batches（发布层）
每层带 who/when/what，AI 提案另带 prompt_version + resource_version
```

## 七、运维

### 7.1 备份

```bash
# 手动备份（全库＋媒体）
bash scripts/backup_db.sh

# 自动备份（crontab）
15 2 * * * cd /path/to/web-word && bash scripts/backup_db.sh --keep 14 >> data/logs/backup_db.log 2>&1
```

备份产物在 `data/backups/db/*.sql.gz`＋`data/backups/media/*.tar.gz`。
词典管理→📤 出版导出→备份新鲜卡确认 ✅。

### 7.2 体检

```bash
./start doctor   # 八类检查（Python/依赖/MySQL/.env/AI 接入/种子数据/数据库基线/端口磁盘）
```

### 7.3 修复

```bash
./repair.sh           # 全量体检报告
./repair.sh --fix     # 自动修复（起 MySQL/重新授权/重灌低于基线的表）
```

## 八、常见问题

| 问题 | 答案 |
|------|------|
| 登录后看不到管理区 | 新号默认 viewer；词典管理员需在「📖 项目成员」入册并授角色 |
| 搜索结果为空 | 数据可能未灌入——看「数据不可用」vs「未灌入」灰注区分 |
| AI 释义没出来 | 检查「🤖 模型供应商」是否有 enabled＋is_default 的供应商 |
| MySQL 连不上 | `./start doctor` 体检；离线模式不崩但功能降级 |
| 释义质量不好 | 模板是编者的语义底座，不是成品——在撰写台改定 |
| 忘记密码 | 联系平台管理员重置（新号默认 viewer，需词典管理员重新授权） |
| 页面加载慢 | 确认不是首次运行（DDL 初始化 6s）；检查 binlog 是否过大 |

## 十、术语表

| 术语 | 含义 |
|------|------|
| **词类** | 词典范畴项目（如 motion 移动动词）＞ 语言学中的词性 |
| **语义范畴** | Levin 次类/域系（如 RUN 跑范畴） |
| **子簇** | 聚类算法产出的语义子群 |
| **义位** | 分析单元（oald_senses.id 唯一锚定） |
| **词条** | 装配成品（头块＋义项区＋例证＋参见） |
| **词目** | 词形层投影（definitions 表） |
| **范畴包** | 词类的配置实体（configs/\<category\>/ 六件套） |
| **coverage** | 建模/沿用/待补——义位是否经过建模流程 |
| **Gower 距离** | 混合特征相异度（binary/nominal 不一致记 1，ordinal 归一差值） |
| **UPGMA** | 非加权组平均法层次聚类 |
| **medoid** | 簇内到其他成员平均距离最小的代表点（原型操作化） |
| **cophenetic** | 共表相关系数（聚类保真度评估） |
| **母图式** | 簇级共享事件框架（特征均值≥0.5 → 共享要素） |
| **四维模板** | 图式/语义参数/句法/对齐预留 |
| **三级权限链** | 建号(viewer) → 入册(项目职能) → 分派(具体簇) |
| **两步激活** | 平台管理员 available → 词典管理员 enabled |
| **G1-G6 闸门** | 准入→编码 / 信度→分析 / 分立→释义 / 撰写→审校 / 审校→装配 / 装配→出版 |
